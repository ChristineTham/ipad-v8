# Shipping Edition

*What the repository already does, and what still needs a human with the Hello
Tham account. Licensing constraints that drive several of these choices are in
[licensing.md](licensing.md) and are binding, not preferences.*

## Done in the build

| Item | Where | Value |
|---|---|---|
| App icon (iOS + macOS) | `app/Edition/Assets.xcassets/AppIcon.appiconset` | Generated by a script, not hand-drawn art — regenerate with `tools/gen-icons.swift` |
| Privacy manifest | `app/Edition/PrivacyInfo.xcprivacy` | No tracking, no collection; declares file-timestamp + UserDefaults API use |
| Export compliance | `INFOPLIST_KEY_ITSAppUsesNonExemptEncryption` | `false` — verified to land as a real boolean, not a string |
| Category | `LSApplicationCategoryType` | `public.app-category.developer-tools` |
| Version | `MARKETING_VERSION` / `CURRENT_PROJECT_VERSION` | 1.0 (1) |
| Copyright | `NSHumanReadableCopyright` | Hello Tham Pty. Ltd. |
| Signing | both targets | `DEVELOPMENT_TEAM = RPL5R637DS` (**org team, never personal**) |
| macOS sandbox | `app/Edition-macOS.entitlements` | App Sandbox + network client/server (loopback only) + user-selected files |
| macOS hardened runtime | `ENABLE_HARDENED_RUNTIME` | `YES` |
| Licences screen | `app/Edition/LicensesView.swift` | Reachable from Settings on both platforms |

## Still needs a person

1. **Decide the final name.** The build ships the working title *Edition*. App
   Store names must be unique, and this one is short enough to be taken. It
   **must not contain "UNIX"** — that is a trademark constraint, not a style
   preference. Safe vocabulary: *Edition 8*, *Research Edition*, *Blit*,
   *5620*, *V8*. Changing it means `INFOPLIST_KEY_CFBundleDisplayName` and the
   App Store Connect record, not the target names.
2. **Register the bundle ID** `com.hellotham.edition` under team RPL5R637DS.
   Both targets deliberately share it, so enable **universal purchase** if the
   iPad and Mac apps should be one product.
3. **Bundle the 2017 statement PDF.** [licensing.md](licensing.md) commits to
   shipping it. It is not in the repo — binaries stay out of git — so fetch it
   into the app resources as a build step before submitting:
   <https://www.tuhs.org/Archive/Distributions/Research/Dan_Cross_v8/statement_regarding_Unix_3-7-17.pdf>
   The licences screen currently links to it instead.
4. **Screenshots** for both platforms (iPad Pro 13-inch and Mac). The obvious
   set: the 5620 at a `login:` prompt, `mux` running with a layer open, `jim`
   editing, and the settings screen.
5. **Privacy questionnaire:** *no data collected*. This matches the manifest;
   they are separate declarations and both must say so.
6. **Price: free.** Not a business decision — the 2017 covenant reaches
   non-commercial use only. No ads, no IAP, ever.
7. **Age rating** and the usual metadata (description, keywords, support URL).

### Review notes worth writing in the submission

App Review has form here: iSH (2020) and iDOS 2 (2021) were both hit under
**2.5.2**, which forbids downloading or executing code the app did not ship.
Say plainly that:

- the app runs **only bundled code** — the disk image is embedded in the app,
  nothing is downloaded, and there is no interpreter for user-supplied
  programs outside the emulated machine;
- it is a **full-system emulator** of a 1985 VAX-11/780, the same category as
  UTM SE and iAltair, both of which ship on the App Store;
- the system it boots is distributable under a **2017 statement from Nokia /
  Alcatel-Lucent** covering non-commercial use, which is why the app is free.

## Archiving

```bash
cd app && xcodebuild -project Edition.xcodeproj -scheme Edition \
  -destination 'generic/platform=iOS' -archivePath build/Edition-iOS.xcarchive archive
```

```bash
cd app && xcodebuild -project Edition.xcodeproj -scheme EditionMac \
  -destination 'generic/platform=macOS' -archivePath build/Edition-macOS.xcarchive archive
```

Both need the V8 media present (`work/myv8/rp06v8.golden` + `bootV8`) — the
"Embed V8 media" build phase warns and produces a medialess app otherwise,
which builds fine and then fails at first launch.

If a Developer ID build is ever wanted alongside the Store one, it needs
notarisation (`xcrun notarytool submit`); the hardened runtime is already on.
